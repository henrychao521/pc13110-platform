# 設計評估：機台認證檢核 + 名單確認系統

> 目標：讓學生**「看完學習＋通過認證」才能操作機台**，且老師能**確認名單**（誰、通過了哪一台、何時）。
> 本文評估架構選項與落地路線，並說明與目前工坊已實作部分的銜接。

---

## 1. 目前已經做好的部分（基礎）

工坊 3D 學習頁（`workshop.html`）每台機台已是一個**闖關式學習模組**，且把認證結果寫進瀏覽器：

- 流程：`認識 → 安全 → 教學影片 → 步驟排序（要做對才能下一步）→ 認證測驗（全對才發證）→ 取得「機台通行證」`
- 通過後寫入 `localStorage` 的 `pc13110_workshop_v1`：
  ```json
  { "learned": {"laser": true}, "passLog": {"laser": 1718...},
    "student": {"name": "01 小明", "room": "901"}, "ts": 1718... }
  ```
- 學生可開「📋 我的通行證」面板，看自己 6 台的認證狀態與時間（可截圖／給老師看）。

**關鍵限制**：`localStorage` 是**「單一裝置／單一瀏覽器」**的。換台電腦、清快取就沒了，老師也**無法一覽全班**。要做真正的「名單確認」，資料必須離開裝置 → 需要一個雲端紀錄。

---

## 2. 三種架構（由簡到完整，建議分階段走）

### Tier 0 — 純單機 + 老師目視（今天就能用）
- 學生在自己裝置完成認證 → 出示「我的通行證」畫面或截圖 → 老師目視確認後，才放行實機操作。
- ✅ 零後端、立即可用、隱私最單純。
- ⚠️ 老師要一台台看、學生可竄改 `localStorage`、無集中名單。
- **適用**：小班、試行期、單堂課。
- 可強化：通行證畫面同時顯示 `班級+座號+機台+時間`；進階可加一段「簽章碼」（把這些欄位做 hash），老師掃 QR 核對，降低竄改。

### Tier 1 — 輕量雲端名單（**建議主力方案**）
用 **Google Apps Script + Google Sheet**（學校友善、免費）或 Firebase：
- 認證通過時，前端 `fetch POST` 一筆 `{班級, 座號, 姓名, 機台, 分數, 時間}` 到雲端表。
- 老師端開一頁 **`roster.html`（認證名單）**，讀同一張 Sheet，顯示**矩陣：學生 × 6 機台**，即時看誰通過哪台、可匯出、可篩班級。
- ✅ 集中、即時、可匯出、伺服器時間戳難造假。
- ⚠️ 要建一個後端端點（Apps Script 約半天即可），需網路。
- **名單防冒名**：以「**班級代碼（老師發）+ 座號**」綁定 → 老師先把班級座號名冊匯入 Sheet，系統只接受名冊內座號；或 roster 端讓老師手動把「通過」核可成「**老師確認**」（雙重關卡）。

**實作要點（很省）**
1. Google Sheet 兩張表：`名冊(班級,座號,姓名)`、`認證紀錄(時間,班級,座號,機台,分數)`。
2. Apps Script 發佈成 Web App：`doPost` 收認證、`doGet` 回名單 JSON。
3. `workshop.html` 的 `certify()` 多加一行：`fetch(APPS_SCRIPT_URL,{method:'POST',body:JSON.stringify(rec)})`（失敗就退回單機，不擋學習）。
4. `roster.html`：抓 JSON → 畫學生×機台勾選表 + 篩班級 + 匯出 CSV。

### Tier 2 — 帳號登入（未來，正式化時）
- 串學校 Google 帳號（OAuth）或平台帳號，身分由登入決定，最防冒名、可跨學期累積。
- ⚠️ 建置與維運成本高。**多班、跨學期、要算正式成績**時才值得。

---

## 3. 檢核強度設計（避免「亂點就過」）

已實作：測驗**全對才發證**。可再加（依需要開關）：
- 題庫**抽題 + 選項隨機排序**（降低背答案）。
- **影片頁最低停留秒數**（看了才放行下一步）。
- 答錯 → 強制**回看安全頁**再作答。
- 認證有效期（例如一學期）；逾期要**複訓**。
- 紀錄分數與作答時間（Tier1 起，伺服器存）。

> 設計原則：檢核是「安全教育的門檻」，不是考試。門檻要**擋得住隨手亂點**，但別讓認真的學生卡關到放棄。

---

## 4. 數位認證 ↔ 實機放行（最重要的銜接）

**數位通過 ≠ 自動能開機**。建議實體配套，把線上認證變成現場可執行的放行：
- **低成本**：老師在 `roster.html` 看到通過 → 發實體「機台證」貼紙／磁扣；或機台旁貼 QR，學生掃→顯示自己該台已認證→老師才給鑰匙／開電源。
- **進階（未來硬體）**：機台電源接刷卡／QR 門禁，只有認證學生能通電。成本高，先不做，但架構可預留。

---

## 5. 建議落地路線

| 階段 | 內容 | 工時 | 何時 |
|---|---|---|---|
| 今天 | Tier 0：通行證面板 + 老師目視（已可用） | 0 | 現在 |
| 期中 | Tier 1：Apps Script + Sheet + `roster.html` 全班名單 | 約 1–2 天 | 試行順了之後 |
| 配套 | 實體機台證／機台旁 QR 核對 | 低 | 與 Tier 1 同步 |
| 未來 | Tier 2 登入、硬體門禁 | 高 | 要正式成績／多班時 |

## 6. 隱私
- 只存 `座號 + 班級 + 機台 + 時間（+分數）`，**不存敏感個資**。
- Google Sheet 權限只給老師；對外頁面只讀不顯示全名（可用座號）。

## 7. 與「設備材料清點系統」共構（省力）
兩套系統可共用：**同一份班級座號名冊、同一個 Apps Script 後端、同一套 QR／3D 互動框架**。先把這層基礎建好，認證與清點都接上去即可。詳見 `設計_設備材料清點系統.md`。
